# 校园 AI 与本地课表验收

## 数据与账户

SQLite 保存学期课表、账号关联的教务快照、稳定本地课程 ID、修改/删除记录及完整历史。独立 AI 课程刷新时保留；普通刷新清除旧教务课程的修改记录；指定保留的修改通过新旧基线匹配后应用。匹配歧义需用户明确。历史恢复生成新版本，旧版本不自动删除。

AI 首次导入允许尚未登录教务。教务首次成功登录或恢复会话自动读取当前学期；无旧教务基线直接缓存，有变化展示更新选项。我的页直接使用缓存，打开不续登 WebVPN。首次引导只在第一次进入我的页消费。其他学期通过本地学期选择器访问；AI 可按指定学期查询教务。

每次写入检查旧 revision 并使用唯一 operation ID，事务同时保存当前数据与历史。AI 每轮先读取数据、汇总所有操作后一次提交；进一步修改用新消息。成绩、选课结果、评教状态只读，密码、Cookie 不进入模型。

## 模型配置、等待与思考显示

每个模型配置独立绑定 API 根地址及密钥；同名模型 ID 可以建立多份配置，内部配置 ID 与请求的模型 ID 分离。设置页仅填写每个模型内部的地址和密钥；外层不再显示重复字段。旧全局地址和密钥仅用于兼容已有配置，编辑旧模型时自动填入其有效配置。API Key 输入框使用普通文本键盘配置，页面自绘遮罩默认隐藏原值，小眼睛切换显示；复制、粘贴仍保留真实内容，不改变已保存密钥。配置元数据存于 SharedPreferences；所有密钥通过现有原生加密安全存储保存为版本化集合，不进入模型 JSON 或会话数据库。编辑和删除配置不会改变其他配置的密钥。

连接、非流式回复和流读取的无数据等待默认 300 秒，可设置为 60–1800 秒；收到数据会重置流读取等待计时。超时会关闭连接并显示可重试提示。不会自动重复发送可能修改课表的请求。

Chat Completions 返回的 `reasoning_content` / `reasoning` 与正文分开解析、保存及显示，可在思考卡片中展开。服务未返回这些内容时不会生成或展示虚构思考。思考内容仅本地展示，不自动发送给下一轮模型。

AI 页不再显示提前授权开关。AI 提交 `patch_schedule` 或 `merge_academic_schedule` 后，软件先校验参数与版本，再展示学期、具体增删改、课程名称、周次、节次和教室，弹窗让用户选择“允许”或“不允许”。允许后才保存本地课表和历史；拒绝、关闭弹窗、页面关闭或停止请求都不会默认同意，同一轮拒绝后不再重复申请。不再依赖“添加/修改”等固定关键词决定是否能申请权限，“加一个课”等表达也可申请。

底部页面切换保留 AI 页；已经开始的模型请求在关闭 AI 子页面后也继续接收并保存正文、思考及工具结果。重新打开可从会话历史恢复。此保证针对应用进程仍存活时的页面切换，不保证系统杀进程或移动系统挂起后的网络执行。

学期选择、周次选择、左右切周、本周及列表切换合并为一行。周课表按可用宽高分配七列和所有节次，不使用双向滚动。仅显示所选周的课程；非本周课程不出现在格子中。课程名及教室按单元格尺寸缩小字体后完整换行；重叠课程分列显示且保持整列高度，避免隐藏课程使整列坍缩。极长课程名或大量时间冲突时字号会较小，可点课程查看完整详情。


读取工具调用本身就是数据申请，自动通过，无需用户弹窗。请求前只提供工具目录、当前问题及附件元数据；贴吧、新闻、教务、本地课表及附件正文在调用相应工具后才发送。工具型模型的附件不再自动附加第一个文字块或图片。旧轮次的原始工具结果、调用详情和附件内容不再重复发送，保留用户问题与助手文字回复；本轮工具调用与结果仍完整配对。`read_schedule` 默认不返回重复的教务原始快照和修改记录，可按week/dayOfWeek筛选；只有合并修改时才显式申请academic_base。

AI 用户消息、助手回复、思考、课表保存结果及来源卡片均支持文字选择和整条复制，整条复制保留正文原始 Markdown。选中菜单使用中文的复制、剪切、粘贴、全选、查询、搜索和分享等标签，保留平台提供的操作能力。应用配置 Flutter 中文 Material/Cupertino 本地化；AI 文本输入和选择区域使用自定义中文菜单，避免英文系统菜单覆盖。

## RikkaHub 源码参考

读取了 [RikkaHub](https://github.com/rikkahub/rikkahub) 的源码版本 `0966502c4d65c1ee4b2a3e49a19703bb1978016c`，重点参考 `ProviderSetting.kt`、`ChatInput.kt`、`ChatMessageReasoning.kt` 及 `ChatService.kt` 的配置绑定、输入、可展开思考和生成任务生命周期。它是 Kotlin/Jetpack Compose 项目；这里独立实现对应的 Flutter 交互，没有嵌入其 AGPL-3.0 Kotlin 源码。当前不是整个 RikkaHub 的功能复刻，使用本项目的 Chat Completions / Responses 协议、校园工具及附件实现。

## 模型与附件

每个模型可开启“支持 Responses API”，开启后调用 `/responses`，默认关闭并使用 OpenAI-compatible Chat Completions。两种协议均支持 SSE 和非流式 JSON 回包、图片与工具调用；Responses 使用 `store=false`，本轮工具继续时回传原始输出项及加密推理上下文。兼容流末尾缺少空行的服务。配置接受 HTTPS API 根路径或完整 `/chat/completions`、`/responses` 地址；仅域名时默认 `/v1`，禁止凭据及查询参数。模型 ID 按原样发送，区分大小写；显示名称仅用于本机列表，输入框明确标注用途。连接成功提示显示实际模型 ID。连接测试展示安全分类错误，`model_not_found` 提示核对模型 ID 或渠道，不显示服务原始错误正文。密钥在原生安全存储中保存，AI HTTP 使用完整日志客户端，逐块保留请求、响应及思考流；本机仅保留最近 24 小时。

文字附件分为 12,000 字符块；DOCX 提取段落和表格段落，XLSX 保留工作表与单元格坐标。PDF 按页提取，扫描页按需渲染交给视觉模型。用户可预览已解析内容。文件大小 20 MB、每消息 5 个，Office 解压内容上限 100 MB；加密或损坏文件会提示转换。文件选择不限制扩展名，并允许无扩展名；直接解析 UTF-8/UTF-16 文本、JPG/PNG/WebP/GIF/BMP、PDF、DOCX、XLSX。图片按文件头识别并转换为 PNG，其他格式（含旧 DOC/XLS、音视频）保留完整原始文件，以明确标注的 Base64 分块提供，不能声称已理解不支持解析的内容。读取多个来源、正文或附件分块可通过 batch_read 一次请求最多 30 项；逐项返回结果，失败不会丢弃其他结果。已获取贴吧主楼或评论的图片可按 URL 申请视觉读取，下载逐块记日志并支持即时取消。大文档最多连续执行 24 次模型步骤，达到边界后保存进度、明确提示继续；不静默丢弃剩余块。

会话消息、工具调用与返回、附件均本地持久化。停止后保留已完成工具结果；重试使用同一任务上下文，不重复执行已保存课表操作。首次发送需同意数据发送提示。删除会话会删除关联本地附件。

兼容 Responses 服务在完成事件中返回空 `output` 的情况：成功完成后使用流中 `response.output_item.done` 已确认完整的结果，保持工具顺序及推理上下文，记录完成事件和恢复内容。失败、未完成或取消时不执行这些调用。无正文且无工具调用的回复显示可重试错误，不保存空助手消息或静默结束课表修改。

## 内容与请求策略

各来源默认 10 条，用户明确数字可提升到 50；客户端按本轮累计限制，重复调用不能追加超过上限。贴吧按发帖时间读取非置顶帖子，再取主楼；评论只有问题提到讨论/回复等才开放，各帖默认 10、最多 50，楼层/楼中楼共用额度。新闻没有有效缓存和正文时返回空或摘要，并明确缺失；AI 不使用 demo 内容。

贴吧正常浏览和 AI 共用请求队列，单次在途，间隔 2 秒，缓存 2 分钟。网络失败最多两次退避重试；403/429、验证码、风控和频繁等错误暂停队列，不自动规避或续刷。用户处理后可手动恢复。取消会阻止排队中的后续 AI 请求；已经送出的原生请求完成后不会继续获取或修改。

正文、评论、新闻与附件为不可信数据，不能自行授权写入。工具白名单不允许任意教务路径、任意网络请求或在线提交。工具返回真实数量和部分失败状态，回答附内容来源链接。

## 设备验收

1. 清除本地数据，首次打开我的出现引导；再次打开应用不重复强制引导。
2. 不登录教务，从文字、课表截图、PDF、DOCX、XLSX 导入；核对周次、单双周、地点与时间，无法判定的信息需追问。
3. 教务登录首次缓存后退出账号、关闭网络、杀进程，仍可查看课表与历史。
4. 教务课表改动后选择暂不更新、普通更新、保留某门课删除操作合并；核对独立 AI 课程保留和其他账号隔离。
5. 自定义主题色、深浅色、AMOLED、320dp、大字体，核对课程块跨节次、非本周课程隐藏、冲突详情、完整周课表无双向滚动、课程名称和教室均无裁切。
6. 配置真实兼容服务，检查流式回复、停止、重试、模型选择、视觉和工具能力错误、引用链接；日志中完整保留 API Key、聊天附件、工具参数及结果，验证最近 24 小时保留范围；关闭页面后检查后台回复及思考保存；不同服务配置同名模型验证地址/密钥互不串用。
7. 读取默认 10 条和明确 50 条，区分正文/评论/楼中楼及发帖/回复时间；遇到限流立即停止，部分结果如实反馈。
8. 删除会话与附件；恢复课表旧版本，再查看历史确认后续版本仍存在。

真实教务、贴吧和 AI 服务验收需要设备、用户账号及用户自带 API Key。模拟 HTTP 与本地数据库测试不能替代外部服务验收。

## WakeUp 时间模型与手动编辑

参考 WakeUp 3.612/3.621 的独立节次时间表、开始节次/跨度布局、课程详情与手动编辑流程；可访问源码分支为 xianfei/WakeupSchedule_BUPT，版本及许可证记录在 third_party/WakeUp/。时间模型与课程数据分开：节次基准来自本地设置或教务大节时间（初始按两节和课间拆分，可在设置校正），每门课可额外设置实际开始/结束时间。

有实际时间覆盖的课程按分钟映射到节次坐标，课间和午休压缩到小间隔，以保留整周适配屏幕的布局。早到、晚到及短课会改变上下边界；课程详情和今日列表显示实际时间。冲突使用实际时间判断；缺少时间表时退回节次范围，不编造时间。

设置 → 修改课表支持新建课表、添加、修改、删除课程，编辑学期、课程名、教室、教师、星期、节次、周次范围、单双周及实际时间。设置 → 修改课表 → 节次时间逐节设置上下课时间；课程详情也可直接进入手动编辑。手动课程保持独立来源，教务刷新保留；手动修改教务课程仍进入可指定保留的修改记录。手动与 AI 编辑共用 revision 校验、事务和历史恢复。实际时间覆盖在历史恢复和保留教务修改的合并中同样保留。

## 按周次修改与冲突提示

AI 按周次新增或修改课程不要求手动填写年月日。读取课表时根据教务或本地已有的日期、教学周自动推算第1周周一，保存时沿用原锚点；缺少日期也可保存周次课程，不猜测开学日期。只有明确校正日期时才提交 startDate。

AI 保存提示只检查涉及本次新增或修改课程的冲突，需星期、实际时间（无时间时用节次）、上课周次同时重叠；删除不带出其他课程之间的旧冲突。提示显示实际重叠周次，相同提示去重。教务整表合并仍检查合并后的所有课程。

## RikkaHub 消息与思考界面

消息布局和思考动画依据固定的 RikkaHub 源码迁移，来源和 AGPL 许可见 `third_party/RikkaHub/README.md`。用户消息使用圆角气泡，头像和名称在上方，复制操作在气泡外；助手 Markdown 正文直接展示，同轮思考与正文共用一个名称行。输入框使用圆角描边卡片，附件与发送/停止按钮位于底部。

接口返回思考时实时显示最多 100dp 的渐隐预览，自动滚动到最新内容，并以 50ms 间隔更新耗时。点击可完整展开，再次点击回到实时预览；第一段正文到达或该轮响应结束时自动收起，显示“思考了 x.x 秒”，可重新展开复制。取消或失败保留已有内容，持久化终止状态和耗时，恢复会话后保持折叠。每次思考更新、完成、展开/收起和复制均记录完整关联 ID、前后内容及结果；网络逐块日志与本机滚动 24 小时保留策略沿用现有实现。

读取工具过程与模型思考共用 Rikka 风格折叠组件：即使 API 不提供思考流，latest_content / 含该工具的 batch_read 也会从开始读取时显示过程框，实时展示读取进度，结果完整保留；第一段正文出现时自动折叠，取消/失败也结束预览。旧会话中的独立 sources 卡片恢复时默认折叠。同一次处理的来源、思考和正文共用模型名称行。

latest_content 的目标数量以用户明确数量为准，未指定时为每个选中来源 10 条（上限 50），不允许模型 count=1 悄悄减少数量。返回 requested / actual / partial 与不足、刷新失败原因，区分“只读一条”与“来源仅返回一条”。数量决策、工具开始/进度/结果/结束、折叠及完整内容均记录关联 ID。

视觉调整：过程卡片折叠态采用与正文同宽的低对比度状态栏，圆角 12dp，去除胶囊边框；图标缩为 16dp，名称行到状态栏与状态栏到正文均留 12dp 间距。展开态延续同一宽度与圆角。输入框默认一行并可增长至五行，圆角 22dp，减少闲置高度；既有过程日志和自动折叠行为沿用。

## 输入框模型、原生搜索与思考程度

顶部模型下拉栏移到输入框左下角，依次为模型、搜索与思考程度图标。模型入口打开选择面板；搜索为开关，思考程度打开包含默认和当前模型已声明档位的面板。生成或附件处理期间禁止改动。会话保存模型、搜索开关与思考档位，恢复时继续使用；未发送的新会话选项留在当前草稿。选择、取消、修改前后、保存、回滚和请求实际采用的参数均有完整日志。

在模型设置中声明“支持模型自带搜索”“支持思考程度”，并选择该模型可接受的档位。旧配置默认不声明支持，避免给原有兼容服务发送未知参数。切换到不支持的模型时不发送相关参数，既有选项仍在会话保留。服务模型能力以所配置服务实际支持为准。

依照 [OpenAI Docs 原生搜索](https://developers.openai.com/api/docs/guides/tools-web-search) 与 [思考参数](https://developers.openai.com/api/docs/guides/reasoning)：Responses 启用 `tools: [{type: web_search}]`，独立于本地工具能力；思考使用 `reasoning.effort`，声明支持思考时请求 `summary: auto`。Chat Completions 搜索使用 `web_search_options`，思考使用 `reasoning_effort`；默认档不发送 effort。当前实现面向现有 OpenAI-compatible 两种协议，不宣称其他供应商的私有搜索参数也兼容。

Responses 原生搜索的服务端事件、查询、返回来源与完成状态接入过程栏，正文开始后折叠；返回的 URL 引用以可点击 Markdown 链接展示，Unicode 字符索引避免截断 emoji。Chat Completions 支持返回的 URL 引用，但该协议未提供的搜索过程不伪造。搜索由模型服务执行，本机可以完整记录发送与收到的 API 请求/响应、事件与引用，无法观察服务商内部的逐个网页 HTTP 请求；此边界同时写入运行日志。日志依旧只在本机保留滚动 24 小时。
